# extra="allow" 支持后的性能复测

> 历史验收记录：本文描述对应审计时点。当前翻译字段契约以[翻译字段边界](../design/translation-boundaries.md)为准；文中未知字段透传、恢复记录及开放模型扩展结论已撤销。

测试日期：2026-10-19 21:50（Asia/Shanghai）。使用真实官方 SDK 和内存 HTTP 响应，排除网络与模型推理等待。

## 结果

完整五协议矩阵共 60 个场景、600 个暖样本，全部通过请求、结果与资源关闭断言。
另做同进程随机交替对照，10 个原生场景共 600 个样本；加入 extra="allow" 处理后的 P50 变化范围为 -0.53% 至 +0.81%，未观察到明显回退。

下面为完整 generate 耗时，单位 ms；流式包含全部事件消费、响应关闭和 stream.result 复制。

| 协议 | 聚合 P50 | 聚合 P95 | 流式 P50 | 流式 P95 |
| --- | ---: | ---: | ---: | ---: |
| Chat | 24.11 | 52.98 | 23.77 | 24.08 |
| Responses | 65.41 | 99.87 | 68.53 | 110.80 |
| Anthropic | 49.21 | 85.17 | 49.29 | 84.18 |
| Gemini | 95.86 | 99.18 | 76.45 | 98.90 |
| Ollama | 23.57 | 62.16 | 23.24 | 62.51 |

这些原生负载覆盖各协议自己的复杂能力；协议之间的耗时差不能直接当作相同工作量的效率排名。

## 方法和环境

- 完整矩阵：五个原生场景及 25 对跨协议组合，各自聚合/流式；每场景额外预热 2 次、测量 10 次。
- 默认规模：12 轮历史、12 个工具、每轮 4 个并行调用、2048 字符输入、8192 字符输出、3 层工具 Schema、8 条嵌套参数记录、96 字符增量、1024 字节 HTTP 分块。
- Python 默认 GC 保持开启，计时使用真实 SDK 的序列化与解析；无 socket、网络等待、模型推理或 sleep。
- 负载构造、验证断言和实例最终关闭不计时；冷调用包含新 MyLLM 的 SDK 客户端延迟创建，Schema 已由预检预热。
- Python 3.12.12，macOS-27.0.1-arm64-arm-64bit。
- SDK / 验证依赖：openai 2.54.0、anthropic 0.125.0、google-genai 1.75.0、ollama 0.6.3、httpx 0.28.1、pydantic 2.14.1。
- 工作区源码版本 1.0.4，Git HEAD `59d1de87665443f80b56d9b5f072efe471ee3c0d`，包含未提交修改。安装包元数据版本另为 1.0.2；本次执行工作区源码。
- 当前 shared/transport.py SHA-256：`4ac498a8cee2e0044efdfd28b0b7c138f9ddc5fc9edda0570059c22e8a3aec8e`。

## 同进程随机交替对照

以当前 shared/transport.py 为基础，对照版本只移除 extra="allow" 编译标记与复制/投影的额外字段分支，恢复本次修改前的字段筛选表达式。
通过切换共享过滤器的 `_plan` 内部入口使用两套独立类型计划；同一 MyLLM 和 SDK 客户端、同一原生负载、同一计时边界，每种实现预热 2 次、测量 30 次。固定随机种子 20261019 打乱 60 次样本顺序。
验证断言在计时外继续执行。默认 GC 开启，并通过 gc.callbacks 记录计时期间的收集次数和耗时。

| 协议 | 聚合 P50：对照 → 当前 | 变化 | 流式 P50：对照 → 当前 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| Chat | 23.82 → 23.72 | -0.43% | 24.13 → 24.08 | -0.20% |
| Responses | 64.50 → 64.60 | +0.15% | 64.55 → 64.66 | +0.17% |
| Anthropic | 49.64 → 49.75 | +0.22% | 49.40 → 49.31 | -0.18% |
| Gemini | 98.84 → 98.48 | -0.36% | 98.28 → 99.07 | +0.81% |
| Ollama | 23.31 → 23.43 | +0.54% | 23.12 → 23.00 | -0.53% |

Gemini 对照的两种实现、两种模式，各有 17/30 个样本在计时期间触发第 2 代 GC，单样本 GC 总耗时的中位数约 42 ms。当前实现的聚合/流式 GC 耗时中位数分别为 41.87 / 42.74 ms。GC 是本负载中可观测的显著耗时来源，样本落在哪一侧会影响 P50。
这组对照使用独立于主矩阵的进程，在该进程内同时保留两套计划、增加 GC 观测；绝对耗时用于该表内比较，不直接替代主矩阵结果。
本次结果支持新增处理分支没有给既有五协议路径带来明显耗时回退。开放模型实际携带的大量扩展数据仍会产生相应的复制、验证和序列化成本，取决于具体 payload。
