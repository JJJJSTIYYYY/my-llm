# 中间协议公开入口验收与性能

> 本文记录当时源码快照的测量结果。原始 JSON 日志已清理，保留结果汇总、测量条件与复测方法；不能再据本文逐样本复算，也不将历史结果视为当前工作区实测。

## 交付范围与证据

2026-10-24，在此前重构和缓存审计的工作区上增加中间模型直接输入输出。没有修改五种原生协议实现、
SDK transport 或既有缓存策略。本文比较同一版本的原生 stdio 与中间模型 stdio，
不替代此前原始重构前后的性能对照，也不表示此前已记录的回退被全部消除。

| 要求 | 落地行为 | 验证依据 |
| --- | --- | --- |
| 导出中间协议，外部可直接构造输入 | 包根导出具体模型及 JsonValue / JsonObject / MessageContent / ResultContent / ItemIdentity；使用 Message / FunctionTool 列表或元组 | [公开导出](../../src/my_llm/__init__.py)、[直接入口测试](../../tests/integration/test_middleware_io.py) |
| 必须显式指定 stdio_protocol | `stdio_protocol="middleware"`，类型化输入不能推断或使用原生 stdio | 直接入口的三种绑定反例、原生字典与非法模型反例 |
| 不增加 codec / encoder / decoder / transport | middleware 名称保留给 stdio，注册表不包含它；每次调用仍只构造上游既有组件 | 跳过组件断言、实例组件集合断言、保留名称注册反例 |
| 请求跳过源 encoder | 完整选项与已校验模型直接进入现有 Decoder.prepare；保留历史、参数、SDK 请求校验 | 五上游 × 两种消费方式，将 Encoder.request 替换为失败函数仍成功；工具关联与非法 max_tokens 反例 |
| 返回跳过目标 decoder | 上游 encoder 和既有 StreamState 累积；返回 AssistantMessage，流式为 MessageEvent | 同十场景将 Decoder.messages / chunks / result 替换为失败函数仍成功 |
| 保持工具、用量和资源语义 | 成功 EOF 后完整调用集中交付，无参数碎片或公开 usage；异常提供具体 partial_message | 五上游提前关闭和截断、取消、同实例真实重叠并发、顶层一次性 helper |
| 保持数据与损失策略 | 输入 JSON 在 SDK 边界捕获；Origin 指向调用者模型；raise / ignore / hook 与原位 draft 身份保留 | 五上游准备后修改工具 Schema / 调用参数 / 结果文本、三种双向损失策略和独立结果断言 |
| 补充性能测试 | 五种上游聚合/流式成对采样、独立内存/缓存及四路屏障并发 | [可复现驱动](../../tests/performance/middleware.py) |

公开的 `MessageEvent` 描述状态机累积后的事件，不暴露原生工具参数操作。
输出能力过滤从 BaseDecoder 移至 `codec/shared/output.py`，由原生 decoder 与中间输出共用；
没有复制五种协议的表达规则。输入来源使用浅层模型信封，应用 JSON 借用至 SDK 边界再捕获，
调用者的模型和 Origin 不被修改。不增加全局输入、Profile、响应或客户端缓存。

使用方式与全部事件字段见[直接使用中间协议](../guides/middleware-io.md)。

## 同负载方法

```sh
.venv/bin/python -m tests.performance.middleware --iterations 15 --warmup 2 --concurrency 4 --json /tmp/middleware-io.json
```

Python 3.12.12、macOS arm64。SDK 版本：openai 2.54.0、anthropic 0.125.0、google-genai 1.75.0、
ollama 0.6.3、httpx 0.28.1、pydantic 2.14.1。以上为测量时的环境版本。

- 同一进程、同一源码，N/M、M/N 交替顺序，分别预热两次、采样十五次。
- 默认复杂负载：12 轮历史、12 工具、每轮 4 调用、2048 字符输入、8192 字符输出、3 层 Schema、8 条嵌套记录。
- 包含图片、工具参数和结果、协议可回放的签名/加密思维；中间夹具在计时外构建并清除 encoder 来源引用，覆盖手动构造模型的来源定位路径。
- 十对实际 SDK 请求 SHA256 相同；响应字节与 HTTP 分块一致。结果按公开格式独立提取并验证，不以减少输入/输出语义换取低耗时。
- 计时包括 generate、输入检查与隔离、真实 SDK 序列化/解析、完整流消费、响应关闭和结果读取；保留默认 GC，不运行 tracemalloc。
- 内存、缓存和并发在计时之外另测。四路响应屏障使所有请求同时活跃；每种格式均两批预热、十五批计时。
- 预热 tracemalloc 不含夹具和客户端构造，包含结果及 HTTP 观测，不是进程 RSS。

运行时源码 SHA256：`0fe6641b397409db7811f8b988a264a7fa7afbc17dc858d80ed392804a8ea38e`。
基准公共代码/夹具 SHA256：`4dcf2cef97addd19f52211fa19588c9c3f21af3e62cd075dd5f12847112e22fd`。
本文保留运行时与公共基准代码摘要，逐次 CPU / prepare / first_event / event_count 样本已清理。

## 结果

单位 ms；变化为中间 stdio 相对原生 stdio，负数表示耗时下降。

| 上游 | 模式 | 原生 P50 | 中间 P50 | P50 变化 | 原生 P95 | 中间 P95 | 四路批次变化 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Chat | 聚合 | 23.122 | 19.869 | -14.07% | 23.643 | 52.054 | -13.12% |
| Chat | 流式 | 24.979 | 21.282 | -14.80% | 25.459 | 51.016 | -15.12% |
| Responses | 聚合 | 62.122 | 57.136 | -8.03% | 95.044 | 57.924 | -7.75% |
| Responses | 流式 | 64.871 | 58.639 | -9.61% | 100.454 | 60.152 | -9.56% |
| Anthropic | 聚合 | 38.954 | 33.410 | -14.23% | 74.442 | 67.509 | -12.99% |
| Anthropic | 流式 | 41.226 | 34.928 | -15.28% | 76.893 | 35.546 | -14.86% |
| Gemini | 聚合 | 29.776 | 23.318 | -21.69% | 32.086 | 60.803 | -23.24% |
| Gemini | 流式 | 31.640 | 24.640 | -22.12% | 70.486 | 25.681 | -22.75% |
| Ollama | 聚合 | 14.304 | 11.466 | -19.85% | 54.331 | 50.709 | -19.31% |
| Ollama | 流式 | 16.775 | 12.887 | -23.18% | 123.971 | 19.513 | -21.38% |

各场景百分比变化的中位数：串行 P50 **-15.04%**、CPU **-15.02%**、四路批次 **-14.99%**。
这是十个场景百分比的中位数，不是合并请求的分位数，也不是网络/模型推理提速。

**P95 未全部改善。** Chat 两种模式和 Gemini 聚合出现中间路径长样本。
十五样本的 nearest-rank P95 就是最大样本，因此尾延迟证据有限；未将这些长样本归因于缓存或其他机制，
不能据此声称稳定的尾延迟提升。测量时未剔除异常样本；当前仅保留统计汇总。

两种返回格式事件数不同：Chat 89/94、Responses 132/118、Anthropic 124/118、Gemini 135/330、
Ollama 110/118（原生/中间）。两边均完整消费，并验证全部正文、思维与工具参数；
中间格式有自己的块生命周期，没有用事件数相同作为等价前提。

| 上游 | 串行原生/中间 peak，约 MB | 四路原生/中间 peak，约 MB |
| --- | ---: | ---: |
| Chat | 7.019 / 7.015 | 12.052 / 12.046 |
| Responses | 7.089 / 7.092 | 12.266 / 12.307 |
| Anthropic | 6.578 / 6.535 | 10.785 / 10.833 |
| Gemini | 5.845 / 3.266 | 18.887 / 8.573 |
| Ollama | 6.852 / 6.852 | 12.066 / 12.066 |

上表为聚合场景、十进制 MB；此处只保留聚合内存探针汇总。除 Gemini 明显下降外，其余内存近似不变，
Responses 和 Anthropic 的部分探针略增，不把它们描述为全面内存改善。

二十次预热缓存探针均无新增 miss，所有并发探针 `peak_active=4`。
现有有界类型规则缓存继续复用，没有新增或扩大缓存。主要工作量变化来自跳过两端协议转换；
输入模型构建成本在本对照之外，若业务每次先做原生到中间转换，应把该成本另行计入。
