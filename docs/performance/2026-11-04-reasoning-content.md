# ReasoningContent 重构性能复测（2026-11-04）

完整 60 场景的 P50 变化中位数为 **-1.18%**；安静环境下 18 场景 ABBA 对照为
**+0.40%**，范围 -1.01%～+1.42%。这支持整体成本接近原实现，不能据单轮数据宣称普遍提速。
最后补齐 Responses 流反馈所有权后，其两项原生场景相对原始实现分别为 **+0.44% / +0.22%**。

使用同一个 Python 3.12.12、官方 SDK、原始性能驱动和原生夹具。完整运行覆盖五协议原生场景 10 项，
以及五种上游 × 五种 stdio × 聚合/流式的交叉场景 50 项。每项 15 个暖样本、3 次预热。
真实 SDK 经 HTTPX MockTransport 消费内存 SSE/NDJSON；计时包含 generate、完整消费、响应关闭和结果读取，
不含实例构造、夹具、断言、最终实例关闭、网络或模型推理。完整请求字节 **60/60 一致**，
夹具、响应、分块、驱动、harness、解释器与依赖均核对一致。

GC 保持启用，两版本使用相同回调记录暂停，回调开销计入该诊断，不与主测绝对时间混用。
最大相对增量是 Ollama 原生流式的 15.942 → 16.167 ms（+1.42%）；
最大绝对增量是 Chat 原生聚合的 22.640 → 22.928 ms（+0.288 ms）。
重构新增了独立反馈路由提取及反馈状态保存；这些是需要实际执行的新工作。
这些工作在既有编码和状态处理循环中完成；当前测量不能将亚毫秒差异进一步归因到单个函数。

诊断共记录 237 次二代 GC，中位暂停 37.76 ms、最大 52.04 ms，与短样本中数十毫秒的尾部尖峰同量级。
因此 P95 保留原始样本，不能仅凭单轮 P95 判断回退。完整主测尾部与最后一次 pytest 进程重叠，
Ollama → Chat 当时出现约 5%～7% 的表面回退；随后在安静环境按新/旧/旧/新成对复测，
聚合 14.537 → 14.495 ms（-0.29%），流式 15.858 → 15.750 ms（-0.68%），未复现该回退。
这次重复使用 `a8e88d1c` 快照；最终版本的 Ollama、Chat 和共享实现与其逐字节一致。

完整主测及 ABBA 的重构源码是 `f80e14be`。最终源码 `51a1f88f` 相对它只有两个文件变化：

- `ResponsesDecoder._messages()` 第 282 行附近重排 reasoning 条件：合法原生字典仍直接回放；
  非法 scalar 记录损失后，输出继续呈现可见 summary，请求仍跳过该项。
- `ResponsesEncoder._snapshot()` 和 `_chunks()` 的原生 reasoning 完整项分别捕获一次 `feedback_item`，
  防止调用者修改原生 chunks 后污染已经返回的中间流批次。这是保持公开对象所有权所需的拷贝。

其余源码逐字节一致。交叉夹具不含 reasoning，不命中这些分支。为实测最后增加的所有权成本，
用原始版本 A、`f80e14be` 版本 B、最终版本 C 按 **A/B/C/C/B/A** 顺序再次测量 Responses 原生两项，
每轮 15 样本、3 次预热，每版本每项合并 30 样本。请求、响应和夹具保持一致。
