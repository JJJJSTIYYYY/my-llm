# 未识别字典保留专项复核

2026-10-17，按明确后的需求完成修复与复核。

## 验收边界

输入范围为各家的标准协议数据及扩展，不包含库内部 `__my_llm_codec_*` 控制结构。
在此范围内保证 **同一 protocol ↔ 中间态** 无损；
字段冲突时**转换值优先于原位置保留值**。标准格式使用 `profile=None`：
源 Encoder 仅转换已识别字段，未知字段留在源字典的原层级；同协议 Decoder
可将未经修改的中间态还原为原始输入。字典输入保留字段值、空容器与 null，
SDK 对象先按其字典表示处理，不承诺保留 Python 对象身份。

**不保证跨协议无损**。中间态虽然保留字段，目标 Decoder 仍可能因为目标协议
没有对应表示而丢弃字段。例如 Ollama 将文本块转换为字符串后无法表达块上的扩展；
这不构成源 Encoder 丢失字段。配置主动关闭思维链等行为也不属于标准协议无损保证。
必要的不透明内容没有可靠的目标表示时，会明确拒绝转换；未知源事件只在同协议透传。
此前以 A → B → A 必须完全相等作为验收条件，超出了这项需求，现予以更正。

## 编码规则与修复

[字段保留辅助](../../src/my_llm/codec/shared/conversion.py)递归移除明确识别的叶子，
保留未知兄弟字段。规则描述已识别输入字段，不限制中间态允许的键。

```text
源：    a.b = v1，a.c = v2
中间态：d   = v1，a.c = v2
```

函数参数、工具结果对象、JSON Schema 是完整的已识别值，连同内部任意应用字典一起迁移。
Responses 工具结果的原生多模态部分列表按内容类型转换；不会将应用结果对象里的 type 等键解释为协议字段。
部分列表元素仍有未知字段时，保留原索引；已完全迁移的前序元素使用空字典占位，
不通过过滤列表来改变后续字段的位置。

本次修复覆盖以下编码路径：

| 输入位置或行为 | 中间态行为 |
| --- | --- |
| Chat `content[i].image_url` / `file` 的未知子字段 | 留在原嵌套容器，不展开到块根部；已识别 URL / 文件内容转换到 source。 |
| Chat / Ollama `tool_calls[i].function` 的未知子字段 | 留在消息根的 `tool_calls[i].function`；已识别调用信息进入语义内容块。 |
| Gemini `parts[i].inline_data` / `file_data` / `function_call` / `function_response` 的未知子字段 | 留在原 `parts[i]` 路径；媒体数据或调用信息进入语义内容块。 |
| Responses 连续 assistant item | 编码阶段逐项保留，不再合并而丢失后续根扩展；目标解码时按目标表示合并。 |
| 工具定义包装与 function declaration 的未知字段 | 保留原包装和声明索引；已识别定义放入内部函数表示。 |
| 五协议流事件根字段、嵌套 delta、调用、媒体、usage 和输出项扩展 | 留在事件原位置；流操作存入内部保留命名空间，避免覆盖源 `type` / `events` 扩展。 |
| 未知字段与转换后字段同名且冲突 | 原字段留在原路径，转换值使用专用 `__my_llm_codec_translated_fields__` 键；转换字段整体优先，保留列表元素和工具参数不会混入转换值。Decoder、历史校验和流累积均按此规则读取。 |
| 思维链与带扩展的内容块共存 | 添加思维块不改变已有内容块的原索引。 |

`__my_llm_codec_source__`、`__my_llm_codec_translated_fields__`、
`__my_llm_codec_function_definitions__`、`__my_llm_codec_opaque_message__`
是编解码器保留命名空间，统一定义在 [keys.py](../../src/my_llm/codec/shared/keys.py)，不属于外部协议扩展。普通源字段不会被当作内部控制键。流式参数缓冲位于请求状态，不占用源消息块的字段。
其中的原始快照用于精确恢复原生表示，例如字符串/块列表、缺省字段、JSON 参数原始格式、
签名和不透明数据。未知字段同时存在于中间态的原路径，不能仅依赖快照声称保留成功。
中间态是内部转换数据，不定义编辑后与原生快照合并的公开 API。
